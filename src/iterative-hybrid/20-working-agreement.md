## Working agreement

- **The user directs.** The user owns priorities, status and the backlog (in their own tracker), taste calls (look, feel, level layout, UX, naming of player- or user-facing things) and changes to the project brief.
- **Who implements is chosen per plan.** When a plan is handed over, the user names the implementer: an agent, the user, or a split by task. Agents implement only plans handed to them and stay inside their scope. When the user implements, the agent reviews on request and does not edit the user's work unless asked.
- **Agents plan on request.** Milestone, feature, implementation, bug-fix and enhancement plans are drafted with the user and approved before work starts (see *Planning*).
- **Agents suggest; the user decides.** Agents propose changes to the brief and the conventions, and candidate skills, at the end of a plan or when they notice the need. Nothing is added to those files without the user's approval.
- **Authorization.** Irreversible, destructive, costly or externally visible actions (publishing, pushing, accounts, purchases, paid API use beyond an agreed budget, deleting work, system-wide changes) need explicit authorization for that action. Git, tool installs and external communication are user-managed unless delegated; a delegation and its boundaries are recorded in `docs/CONVENTIONS.md`.
- **Preserve work.** Do not reset, clean, move or overwrite unrelated material. Completed plans are never edited (see *Planning*).
- **No sub-agents** unless the user or the project's instructions ask for them.
- **The records must stand alone.** Any session can stop and any agent client can resume from the files: the plan being worked on, `docs/plans/HISTORY.md` and the conventions, never from chat memory.
